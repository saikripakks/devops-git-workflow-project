
# DevOps Git Workflow Project

## Overview
This project demonstrates Git and GitHub best practices as part
of my DevOps Internship Task 4.

## Objectives
- Initialize and manage a Git repository.
- Follow a main, dev, and feature branch workflow.
- Use commits with meaningful messages.
- Create pull requests and merge changes.
- Practice merge conflict resolution and git stash.
- Use .gitignore and Git tags.
- Document commands and interview questions.

## Repository Structure
```text
.
├── README.md
├── .gitignore
├── docs/
│   ├── git-commands.md
│   ├── branching-strategy.md
│   ├── interview-questions.md
│   └── merge-conflicts.md
└── scripts/
    └── system-info.sh
```

## Branching Strategy
- main: stable project version
- dev: integration branch
- feature/*: individual improvements

## How to Run
Make the sample script executable and run it:

```bash
chmod +x scripts/system-info.sh
./scripts/system-info.sh
```

## Git Workflow
1. Create a feature branch from dev.
2. Implement and test the change.
3. Commit with a meaningful message.
4. Push the branch to GitHub.
5. Open a pull request into dev.
6. Merge dev into main through a pull request after validation.
7. Create a version tag for the release.

## Deliverables
- GitHub repository
- Branching and commit history
- Pull request workflow
- Git documentation
- Merge conflict and stash examples
- Version tag

## Learning Outcome
Learn practical version control, collaboration, and release
management using Git and GitHub.
